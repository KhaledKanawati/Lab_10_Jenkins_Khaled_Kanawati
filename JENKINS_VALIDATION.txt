3. Prepare the Jenkins machine

- Use the course Jenkins server, or an already installed supported Jenkins.
  Follow the lab's initial unlock/admin setup only if this is a fresh server.
- Verify Git and Pipeline plugins. This pipeline also uses the JUnit plugin.
  Install SSH Agent as the handout requests; this local deployment does not
  call SSH and needs no remote-server credentials. It uses built-in deleteDir
  instead of cleanWs, so Workspace Cleanup is not needed for this Jenkinsfile.
- The chosen agent needs Git, Python with pip and venv, writable workspace,
  and access to the repository and Python package index. Python 3.11/3.12 is
  recommended; the recorded local run used 3.12.14.
- Windows: "python --version" must work for the Jenkins service account.
  Linux/macOS: "python3 --version" must work; install the distribution's venv
  package if Python reports that ensurepip or venv is unavailable.
- For a private Git repository, configure Jenkins SCM credentials and select
  them in the job. Do not put a token in the repository URL or source files.

New Item -> Python-CI-CD -> Pipeline -> OK.

The pipeline chooses the virtual-environment interpreter path using isUnix().
It does not activate a shell environment, so it works with Windows bat and
POSIX sh without the handout's shell-specific "source" command.

Common fixes

"Jenkinsfile not found": check Script Path, case, repository root and branch.
"python not found": fix the build agent's service-account PATH and restart
the agent/service if needed. Python must be installed on that agent.
"No such DSL method junit": install/enable JUnit, then rerun.
Checkout denied: verify Git plugin, repository access and SCM credentials.
Package download denied: configure the agent's proxy or approved package mirror.
Coverage below 90%: inspect Missing lines and tests; the stage intentionally fails.
Bandit nonzero status: inspect the JSON finding or scan error and fix the cause;
do not use --exit-zero to disguise a failed security check.
